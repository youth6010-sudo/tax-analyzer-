# 미수관리 — 고정 vs 업로드 (전체 구조)

기준일: **2026.08.31 공문 확정본** 위에 **9월~만** 얹음.  
확정본 = 저번주(2026-09-15) 법인조정료 원문 복구 이후 LIVE 공문 상태.

---

## 한 줄 요약

| | 무엇이 | 누가 바꾸나 |
|--|--------|------------|
| **고정** | 8월 31일까지 공문 줄(기장·조정료·입금 내역) | 업로드로 **안 바뀜**. 공문 수정모드·관리자 스크립트만 |
| **업로드로 변경** | 목록 **잔액** + **9월 이후** 공문 줄 | 현황표 + 거래처별 두 파일 함께 반영 |

## 1. 고정되는 것 (올리지 않아도 / 올려도 유지)

### ① 공문 cutoff — `2026.08.31`
- 이 날 **포함·이전** 공문 상세는 동결.
- 거래처별 엑셀을 올려도 **9월~ 거래만** 공문에 추가.
- 7·8월 기장·입금을 업로드가 지우거나 다시 조립하지 **않음**.

### ② 저번주 확정한 표시 규칙 (코드)
- **법인조정료 등**: 공문 원문 유지. asOf 연도 임의 부착 금지.
- **기장 사이에 낀 조정·성실**: 화면에서 연도 숨김 가능.
- **성실**: 원문에 연도 있을 때만 유지.
- Neon(`PREV`)으로 공문 **통째 덮어쓰기 금지**.

### ③ 예외 업체 (코드에 박힘)
| 코드 | 상호 | 동작 |
|------|------|------|
| 00130·00131·00229 | 티밸류홀딩스·매거진·예윤 | 잔액=공문합이어도 **불일치(원장)** 강제 |
| 00183·00199 | 오프라인·하나비 | 거래처별 자동 반영 **제외**, 공문 수동 |
| 담당=인디 | — | 거래처별 파일 **스킵**. 잔액만 현황표, 상세는 기존 공문 |

### ④ 불일치 판정 공식 (고정)
```
불일치 = 현황표 잔액 ≠ 공문 Σ(금액 − 지급)
```
가짜 줄(`미수반영(현황맞춤)`)로 맞추지 않음.

## 2. 업로드하면 바뀌는 것

화면: **미수관리 → 엑셀 업로드 → 두 파일 함께 반영**  
파일명: `미수수수료 거래처(잔액)현황_날짜` + `거래처별 현황_날짜`

### ① 현황표 (잔액 파일)
| 바뀜 | 안 바뀜 |
|------|---------|
| DB **잔액**·이월·차대 | 공문 줄 |
| 기준일(`statusAsOfDate`) | cutoff(항상 8/31) |
| 담당(수임처 미연결 시만) | 수임처 연결된 담당 |
| 관리분류·해임·CMS·메모 | |

→ 목록에 보이는 **숫자 잔액**의 기준.

### ② 거래처별 현황
| 바뀜 | 안 바뀜 |
|------|---------|
| **9월~** 기장·입금 줄 추가/교체 | **8월까지** 공문 전체 |
| | 수정모드 **manual** 줄 |
| | 인디·오프라인·하나비 |

추가 규칙:
- 공문에 **기장 미납이 한 달이라도 있으면** → 매출·입금 쌍을 생략하지 않음 (도리·아이스테형).
- 기장 미납이 **없으면** → 같은 달 매출+입금 즉시회수 세트는 공문에 안 넣음.
- 현황=말잔이고 공문합도 이미 같으면 → 9월을 **또** 넣지 않음 (이중입금 방지). 다만 기장 미납이 있으면 예외.

┌──────────────┐    ┌──────────────────────────┐

## 4. 실무에서 이렇게 쓰면 됨

| 하고 싶은 일 | 방법 |
|--------------|------|
| 매월 최신화 | 그달 **현황표 + 거래처별** 둘 다 업로드 |
| 8월 이전 내역 고치기 | 업로드 ❌ → 공문 **수정모드** 또는 관리자 |
| 기준일만 바꾸기 | 화면 상단 기준일 (cutoff는 그대로 8/31) |
| 인디 상세 | 웹 거래처별로는 안 됨 → 수정모드 |
| 백업 | `npm run db:backup` 또는 미수 스냅샷 JSON |
