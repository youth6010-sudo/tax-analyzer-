# 미수관리 — 고정값 vs 웹 업로드 처리

업로드할 때마다 결과가 흔들리지 않게, **코드/설정에 고정된 것**과 **웹에서 올릴 때 바뀌는 것**을 구분한다.

---

## 0. 가장 중요 — 2026.08.31 공문·잔액 고정

**2026.08.31 기준으로 맞춰 둔 공문 상세·잔액은 고정본이다.**  
이후 업로드는 **그 위에 9월(cutoff 다음날)만** 추가한다.

| 하면 안 되는 것 | 이유 |
|----------------|------|
| Neon(`PREV_DATABASE_URL`)으로 공문 통째 덮어쓰기 | Neon은 예전 스냅샷. 08.31 최종 정리(가짜 7·8월 제거 등)이 없음 |
| cutoff **이전** 월 줄 삭제 | 8월까지는 고정. import/strip이 지우면 안 됨 |
| `미수반영(현황맞춤)` 같은 가짜 줄로 잔액만 맞추기 | 상세가 사라짐 |

| 해야 하는 것 | |
|--------------|--|
| 08.31 맞춘 직후 | **관리자 백업** 또는 `npm run db:backup` 으로 JSON 보관 |
| 9월 반영 | 현황표 + 거래처별 **9월 파일만**, cutoff 8/31 유지 |
| 되돌리기 | Neon이 아니라 **그 백업 JSON** 또는 Supabase PITR |

## 1. 앞으로 업데이트해도 그대로인 것 (코드 고정)

배포 코드에 박혀 있어서, 엑셀을 다시 올려도 **자동으로 풀리거나 덮이지 않는다.**  
바꾸려면 개발자가 코드를 수정·배포해야 한다.

| 고정 항목 | 값 | 의미 |
|-----------|-----|------|
| 공문 cutoff | **2026.08.31** | 이 날 **이후(9월~)** 거래만 「거래처별 현황」에서 공문에 추가. 8월까지 공문 줄은 유지. |
| 강제 불일치(원장) | `00130` (주)티밸류홀딩스<br>`00131` 티밸류매거진(주)<br>`00229` (주)예윤 | 현황표 잔액 = 공문합이어도 목록에 **불일치(원장)** 표시. 실제 거래처원장과 다르다고 인디 확인한 분. |
| 공문 보호(자동 반영 제외) | `00183` 오프라인<br>`00199` 하나비 | 거래처별 현황·잔액 맞춤 자동화에서 제외. 공문 수동 유지. |
| 목록 항상 표시 | `00183` | 잔액 0이어도 목록에 남김. |
| 인디 담당 | 담당명 = 인디 | **거래처별 현황 파일 반영 스킵.** 잔액은 현황표만, 상세는 기존 공문. |
| 양수도 참고 | `00637`↔`01418` 천돈가 | 참고용. 불일치/업로드 예외는 없음. |

소스: `lib/arrearsBalanceLock.ts`, `lib/arrearsImportConfig.ts` (`ARREARS_FROZEN_LETTER_CUTOFF`)

### 티밸류·예윤 3곳 — 질문에 대한 답

**맞다. 웹에서 두 파일을 다시 올려도 「불일치(원장)」은 유지된다.**  
판정이 코드 고정이라, 공문합을 맞춰도 배지가 사라지지 않는다.

## 2. 웹에서 올리면 바뀌는 것

화면: **미수관리 → 엑셀 업로드 → 두 파일 함께 반영**

### ① 미수수수료 거래처(잔액)현황_`날짜`

| 동작 | 설명 |
|------|------|
| 잔액·이월·차변·대변 | **현황표 숫자로 DB 잔액 갱신** (목록 「잔액」의 기준) |
| 담당 | 수임처 미연결일 때만 현황표 담당코드 반영. **연결 수임처가 있으면 수임처 담당 우선** |
| 관리분류·해임구분·CMS·메모 | 현황표에 값이 있으면 갱신 |
| 목록 기준일 | 파일/화면 기준일로 `statusAsOfDate` 저장 (DB `app_config`) |
| 공문 줄 | **건드리지 않음** |

### ② 거래처별 현황_`날짜`

| 동작 | 설명 |
|------|------|
| 대상 | cutoff **다음날(9월~)** 거래만 |
| 유지 | cutoff 이전 **공문(letter)** 줄 + 수정모드 **직접입력(manual)** |
| 제거 후 재구성 | cutoff 이후 예전에 넣었던 ledger/payment 등 → 파일로 다시 채움 |
| 스킵 | **인디** 담당, **오프라인·하나비**(보호코드), 거래중단 코드, 미수 목록에 없는 코드 |
| 즉시회수 생략 | 공문에 기장료 미납이 **없으면**, 같은 달(또는 직후) 매출+입금 세트는 공문에 안 넣음 |
| 이미 맞는 업체 | 현황=말잔이고 공문합도 같으면 **9월 거래를 또 넣지 않음** (이중입금 방지) |
| 8월까지 공문 | **출처(letter/ledger) 무관하게 유지.** 9월~ 월기장만 파일로 교체 |
| 초과분 정리 | 공문합 > 현황이어도 **9월 이후 ledger만** 제거. 8월 이전은 삭제 안 함 |
| 엑셀끼리 다른 업체 | 말잔 ≠ 현황이면 그대로 → 「불일치」 (원래 불일치) |

> `미수반영(현황맞춤)` 같은 가짜 조정 줄은 쓰지 않음.  
> 안 맞으면 「불일치」로 두고, 상세는 실제 월·적요만 유지.

### ③ 목록 「불일치」 판정

```
불일치 = 현황표 잔액 ≠ 공문·상세 Σ(금액 − 지급)
```

예외:

- 공문 없고 내역합 0 · 잔액만 있음 → **원장만(장기미수)**
- `00130`/`00131`/`00229` → 위와 같아도 **불일치(원장)** 강제

## 3. 왜 “올릴 때마다 이상하게” 느껴졌는지

1. **잔액(현황)** 과 **공문 줄**이 서로 다른 파일·규칙으로 갱신됨  
2. 9월 입금만 공문에 넣으면, 이미 현황에 반영된 입금이 **이중**으로 잡혀 어긋날 수 있음 → 지금은 “현황=말잔이고 이미 맞으면 9월 추가 생략”으로 완화. **잔액만 맞추려고 가짜 줄(`현황맞춤`)을 넣지는 않음**  
3. **인디**는 거래처별 파일에 없어서, 올릴수록 현황만 바뀌고 공문은 예전 그대로 → 원장과 다르면 수동/강제 불일치로 관리  
4. cutoff(8/31) **이전** 공문은 업로드로 다시 만들지 않음 → 예전에 틀린 공문은 파일이 고쳐 주지 않음 → **불일치**로 보임 (상세를 속이지 않음)

## 4. 한눈에 보는 흐름

```
[현황표 엑셀] ──► DB 잔액·담당(일부)·기준일     ← 목록 숫자
[거래처별 엑셀] ─► 9월~ 실제 거래만 공문 줄로 추가
                 └► 이미 맞으면 추가 생략 (이중입금 방지)
[코드 고정] ────► cutoff 8/31, 인디스킵, 보호코드,
                 티밸류·예윤 강제 불일치(원장)
```

## 5. 실무 체크

| 하고 싶은 일 | 방법 |
|--------------|------|
| 기준일만 바꾸기 | 미수관리 상단 기준일 (공문 cutoff는 안 바뀜) |
| 잔액·공문 최신화 | 두 파일 **함께** 반영 (파일명 형식 필수) |
| 인디 상세 맞추기 | 웹 거래처별 업로드로는 안 됨 → 공문 수정모드 또는 별도 반영 |
| 티밸류·예윤 불일치 빼기 | 코드에서 `ARREARS_FORCE_MISMATCH_CODES` 제거 후 배포 |
| 강제 불일치 업체 추가 | 같은 Set에 코드 추가 후 배포 |
